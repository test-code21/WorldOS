# WorldOS — Open Design Questions

These questions are intentionally unresolved.

They should not be filled with confident-sounding defaults merely to complete the architecture.

## 1. Recognized-country registry

Which external standard or standards should define the initial country/place registry?

The answer should be generic, transparent, and capable of handling disputed or partially recognized entities without forcing WorldOS to settle political recognition disputes itself.

## 2. Public availability

What exactly counts as a source that WorldOS is permitted to capture?

Publicly reachable does not automatically mean freely redistributable.

The project needs a careful distinction between:

- discoverable metadata;
- retrievable content;
- locally cached content;
- redistributable content;
- copyrighted material;
- public-domain material;
- licensed/open data.

## 3. Full-text preservation

When should WorldOS retain full text, an extract, metadata only, or a hash/reference?

This must balance usefulness, copyright, reproducibility, storage, and source disappearance.

## 4. Entity extraction

How much semantic interpretation is acceptable in the public core?

Extracting a literal named string is relatively mechanical.

Resolving that string to a canonical real-world entity can require interpretation.

The boundary needs explicit testing.

## 5. Relationships

What types of relationships between records can WorldOS safely expose without turning retrieval assistance into unearned interpretation?

## 6. Translation

Should WorldOS preserve only original-language text and let consumers translate, or maintain derived translations for cross-language retrieval?

If translations are stored, their derived status and model lineage must remain visible.

## 7. Dynamic pages

How should WorldOS version sources that change continuously?

## 8. Deletions and corrections

What happens when a publisher removes or corrects public material after WorldOS has observed it?

The project should preserve historical integrity while respecting applicable legal and ethical requirements.

## 9. Model-assisted structure

Which transformations should use deterministic parsers first, and where do LLMs provide enough benefit to justify their use?

## 10. Neutrality tests

How do we test that infrastructure decisions are not quietly privileging:

- English-language sources;
- high-resource countries;
- large publishers;
- Western institutions;
- search-engine popularity;
- or sources that are easier for our models to parse?

## 11. Open dataset vs open software

Which WorldOS outputs can responsibly be distributed as a shared public dataset, and which should be generated by each deployment from public sources?

This requires more thought before the project promises a globally redistributed corpus.

## 12. Canonical next step

Before expanding the ontology, build the smallest end-to-end flow:

> **public text → preserved source → machine-readable structure → provenance-preserved retrieval**

Then evaluate what additional structure is genuinely necessary.
