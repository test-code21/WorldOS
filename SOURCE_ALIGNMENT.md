# Source Alignment

This package is derived from the bundled canonical WorldOS founding materials.

## Canonical ideas carried forward

### Founding Charter
- public, generic, provenance-preserving substrate;
- no preferred country or worldview;
- public implementation is the real implementation;
- WorldOS ends before final intelligence/interpretation.

### Jurisdiction
- WorldOS has jurisdiction over information flow;
- mechanical/contextual transformations are acceptable when lineage is retained;
- interpretive labels belong downstream;
- source identity, dates, revisions, and context are valuable even when WorldOS withholds judgment.

### Architecture Doctrine
- WorldOS composes with SourceLedger, IntelOS, and ModelOS rather than duplicating them;
- GCP is a strong reference deployment but the public code should remain portable;
- models may assist machine-readable transformation if outputs remain derived and traceable.

### Open Source Principles
- public repository is canonical;
- no preferred narrator;
- important transformations should be inspectable;
- commercial hosting/support may exist without degrading the public project.

### Text-First MVP
- text is the first wedge;
- Source, SourceVersion, Segment, and derived structure are useful minimal concepts;
- provenance-preserved retrieval is the first success condition.

### Open Design Questions
- capture/redistribution rights require explicit treatment;
- entity resolution, translation, dynamic pages, deletions/corrections, and dataset distribution should not be solved casually;
- neutrality tests should watch for structural privilege toward English/high-resource sources.

## Legacy note

`reference/legacy/WORLD_MUST_REMAIN_OUTSIDE_MODEL_LEGACY.md` is preserved because some concepts remain philosophically useful, but its Country Model/Australia/reference-environment direction conflicts with the newer canonical charter and is not implementation doctrine for this decade.
