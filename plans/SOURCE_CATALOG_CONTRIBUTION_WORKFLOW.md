# Source Catalog Contribution Workflow

A community source contribution should be reviewable like code.

## Proposed flow

1. Contributor adds/edits source manifest entry.
2. Schema validation runs.
3. URL/adapter smoke test runs where safe.
4. Duplicate/conflict check runs.
5. Contribution describes why the source is operationally relevant (e.g. official regulator, public notice feed), not whether the publisher is ideologically trustworthy.
6. Reviewer checks metadata, preservation mode, cadence, and jurisdiction mapping.
7. Merge updates coverage manifest.

## Useful contribution metadata

- source name;
- public URL;
- institution/publisher identity;
- source class;
- language declaration where clear;
- jurisdiction reference;
- adapter;
- preservation mode recommendation;
- operational notes;
- evidence that URL is intended for public access.

## Avoid

- reliability ratings;
- political labels;
- "good media" / "bad media" categories;
- popularity-driven ranking as a proxy for importance.
